# Проверка источника Fonbet

Дата проверки: 2026-08-17. Сетевой маршрут: VPN пользователя; регион выхода не
фиксировался и не считается свойством источника.

## Статус доказательства

`https://line-lb51.bk6bba-resources.com` — **операционно подтверждённый кандидат
line-host**, но не документированный публичный API. Основной `https://fon.bet` с
текущего IP возвращает JavaScript anti-bot challenge/Forbidden, поэтому автоматически
доказать связь доменов через frontend network log не удалось.

Кандидат принят только как настраиваемый runtime endpoint, потому что прямой HTTP GET:

```text
GET /events/listBase?scopeMarket=1600&lang=ru
```

вернул HTTP 200 и `application/json`. Полученный каталог содержал турнирные узлы и
события, согласующиеся с официально индексируемыми страницами Fonbet: FC 26 UEL,
FC 26 H2H, FC 26 ESportsBattle, NHL 26 UEL/H2H/ESportsBattle. Base URL отсутствует в
исходном коде по умолчанию и задаётся `FONBET_BASE_URL`.

## Подтверждённый контракт

На реальном smoke run:

- `packetVersion`: `82620701764`;
- входных событий: `7 479`;
- целевых турнирных узлов: `16`;
- корневых событий целевых турниров: `202`;
- извлечённых factor quotes: `4 242`;
- rejected events: `0`;
- HTTP + archive + parse: примерно `1 024 ms`.

Наблюдаемые верхнеуровневые массивы: `sports`, `events`, `customFactors`,
`eventMiscs`, `eventBlocks`, `liveEventInfos`. Событие связывается с турнирным узлом
через `events[].sportId → sports[].id`. Коэффициенты связываются с событием через
`customFactors[].e → events[].id`.

Запрос детальной линии наблюдался в HTTP-контракте:

```text
GET /events/event?eventId=<id>&scopeMarket=1600&lang=ru
```

Для уже завершённого события он возвращает HTTP 200 с пустым списком, поэтому не
используется как источник истории. Попытка `GET /events/factorsCatalog?lang=ru`
вернула 404.

## Подтверждённые базовые factor ID

17 августа 2026 года текущая официальная страница Fonbet Cyprus и сохранённый RAW
line-host одновременно содержали событие `England (IcyVeins) — Germany (Djimbo88)`.
Официальная таблица явно задавала порядок колонок `1, X, 2`, затем форы сторон `1, 2`
и тотал `O, U`. Последовательность значений совпала с RAW:

| factor ID | RAW | Официальная колонка | Нормализованный selection |
|---:|---:|---|---|
| 921 | 1.95 | 1 | `P1` |
| 922 | 3.50 | X | `X` |
| 923 | 3.55 | 2 | `P2` |
| 927 @ 0 | 1.45 | handicap 1 | `F1(0)` |
| 928 @ 0 | 2.55 | handicap 2 | `F2(0)` |
| 930 @ 2.5 | 2.35 | over | `TB(2.5)` |
| 931 @ 2.5 | 1.52 | under | `TM(2.5)` |

На официальной странице under уже был 1.53: это ожидаемое движение линии между двумя
моментами получения, а не изменение порядка. Jurisdiction-specific event ID различались,
поэтому сопоставление основано на участниках, времени, линии и всей последовательности
коэффициентов, а не на числовом event ID.

Источники доказательства: [официальная страница события](https://fonbet.com.cy/sports/football/category/118/134077/66897816)
и воспроизводимая запись `research/fonbet_factor_evidence.json`. Только перечисленные
семь ID теперь нормализуются. Все остальные по-прежнему сохраняются как
`unmapped_factor`.

## Что намеренно не утверждается

- endpoint не объявляется стабильным или официально поддерживаемым;
- числовым `factor_id` вне семи доказанных базовых ID не присваиваются названия рынков;
- `packetVersion` не трактуется как timestamp;
- доступность через другой VPN/регион не гарантируется;
- значения `sportId` и `factor_id` не хардкодятся как вечные идентификаторы.

Неизвестные строки сохраняются как `unmapped_factor` с исходным `factor_id`, `v`,
`p/pt`, ссылкой на RAW payload и локальным `received_at`. Это позволяет переиграть
parsing после подтверждения остальных рынков без потери истории.

## Live score не равен подтверждённому результату

В base snapshot у live-событий наблюдаются `eventMiscs.score1/score2`, таймер и
`liveEventInfos`. Контрольное FC26 H2H событие `67277469` было видно со счётом 3:0 и
таймером 90:00, но без отдельного terminal/finished status; в следующем snapshot оно
исчезло сразу из `events`, `eventMiscs` и `liveEventInfos`. Исчезновение может означать
завершение, отмену или переход в другой контракт и поэтому не используется для
settlement.

Официальная страница [Fonbet Results](https://fonbet.com/results) существует и
индексирует завершённые FC26 H2H матчи, однако прямые HTTP-проверки доступных доменов
вернули anti-bot/Cloudflare/QRATOR ответы. Подтверждённый JSON results endpoint не найден.
`FonbetResultsProvider` поэтому намеренно не создан. Воспроизводимое наблюдение записано
в `research/fonbet_result_status_evidence.json`; settlement сейчас опирается только на
результаты подтверждённых исторических providers, например UEL.
