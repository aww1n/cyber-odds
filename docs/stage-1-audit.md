## Архитектурные границы

- Provider получает и архивирует неизменённый HTTP-ответ; Parser отдельно преобразует его
  в source DTO. Изменение endpoint'а не затрагивает остальную систему.
- Normalization создаёт канонические сущности и review для сомнительных fuzzy-совпадений.
- Event matcher связывает source event с bookmaker event и блокирует прогноз ниже порога.
- Odds snapshot только добавляется; prediction ссылается на конкретный snapshot.
- Feature builder принимает `as_of` и на уровне запросов требует `observed_at < as_of`.
- Модели отделены от signal policy: вероятность сохраняется даже для `skip`.
- Backtest использует тот же pipeline и timestamp semantics, что и live worker.
- Research-примеры физически и логически отделены от production observations.

## Следующий gate

До реализации Fonbet provider требуется подтвердить endpoint независимой ручной проверкой,
сохранить реальный RAW-ответ и описать наблюдаемую схему. Если endpoint не подтверждается,
следует зафиксировать это как ограничение и оставить заменяемый provider interface — не
создавать фиктивный collector.
