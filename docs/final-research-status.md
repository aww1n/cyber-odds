# Текущий итог исследования

Дата среза: 2026-08-17. Этот документ разделяет проверенные факты, инженерную
готовность и ещё не доказанные свойства стратегии.

> Это исторический исследовательский срез. Он не описывает текущую runtime-конфигурацию:
> после этого среза UEL forward-алерты были включены оператором для накопления результатов.

## 1. Вероятные источники данных

- Текущая линия: настраиваемый Fonbet line-host, операционно проверенный прямыми
  JSON-запросами и сопоставлением с текущей официальной страницей события. Это не
  объявляется документированным или стабильным публичным API.
- История ESportsBattle: официальный API `football.esportsbattle.com/api`.
- История UEL eFootball/eHockey: официальный frontend-контракт
  `api.unitedleagues.gg`.
- H2H GGL: официальный Hudstats API, на который ссылается SIS. Это отдельный пул и
  не история Fonbet FC26 H2H Liga.
- Надёжный источник истории целевого FC26 H2H Liga пока не подтверждён. Публичная
  CyberFifa-страница прямо помечает данные как демонстрационные и отвергнута.

## 2. Расшифрованные поля существующего бота

На примерах из постановки воспроизводятся:

- `P_target = v / odds`;
- `fair_odds = 1 / P_target`;
- `value_percent = (v - 1) * 100`;
- `safety_multiplier = mo / fair_odds`;
- для `FON_ml_v1`: `bet_mul = min(3, max(0, (v - 1) * 10))`.

Поле `un` хранится как самостоятельное наблюдение и не расшифровывается без данных.

## 3. Математически подтверждённые формулы

Чистые функции value/fair odds и capped bet multiplier покрыты unit tests. На полном
примере FON_ml_v1 расчёт даёт `P=0.5744186`, `fair=1.7408907`, multiplier порога
`0.9994884` и `bet_mul=2.35`, то есть совпадает с округлёнными полями примера.

Важно: входные четыре записи — примеры из спецификации, а не независимо проверенные
исторические алерты. Поэтому подтверждена внутренняя математическая согласованность,
но не происхождение значений реального стороннего бота.

## 4. Формулы, которые остаются гипотезами

- неизвестная функция `historical_data -> P_target`;
- safety multiplier по source/market/strategy;
- трактовка `un`;
- причинность session/team/tournament features;
- прибыльность любого порога value;
- правило расчёта финального результата Fonbet из line JSON: live score виден, но
  terminal status не найден.

## 5. Лучшая модель

Воспроизведение `P_target` пока невозможно оценить: нет набора независимо подтверждённых
исторических алертов с timestamp и доступной на тот момент историей.

Для обычного прогноза результата UEL лучший из проверенных кандидатов — простой
`individual_h2h_fixed`. На 1 460 будущих OOS-событиях он получил LogLoss 1.0704,
Brier 0.6470 и accuracy 40.96%. Это лучше uniform и Logistic Regression v1, но не
доказательство betting edge.

## 6. Out-of-sample устойчивость

Использованы три rolling fold: 8 суток train, 4 validation, 4 test. Fixed baseline
по fold получил LogLoss 1.0750, 1.0459 и 1.0895. Последний fold хуже второго, поэтому
устойчивость не объявляется доказанной.

Окна 5/10/20/25/30/50/75/100/200/all-time сравнены тем же протоколом. Для формы
игроков all-time (1.0726) и last-200 (1.0728) были лучше коротких окон; last-5 дал
1.1425. Для H2H лучший отдельный кандидат last-75 дал 1.0872, а last-5 — 1.1586.

## 7. Реальный ROI

Не рассчитан и не заявляется. Текущая собственная линия охватывает только десять RAW
snapshot за примерно 28 минут, а OOS-результаты относятся к более раннему интервалу.
Соединять их задним числом было бы leakage/подменой данных.

## 8. Calibration

- `individual_h2h_fixed`: OOS calibration error 0.0166;
- Logistic Regression v1 после validation-only выбора isotonic: 0.0697;
- ML хуже baseline по LogLoss, Brier, calibration и accuracy и выключена.

## 9. Максимальная просадка

Не рассчитывается без честного набора исторических bets на реально доступных в момент
решения odds snapshots. Backtest engine умеет считать max drawdown и losing streak,
но выдавать число на синтетическом соединении запрещено.

## 10. Статистически значимые стратегии

На текущем срезе ни одна betting strategy не объявляется статистически значимой или
прибыльной. `individual_h2h_fixed` — только лучший probability baseline и кандидат для
дальнейшего накопления forward-данных.

## Операционный срез

Локальная исследовательская БД содержит 3 371 событие, 2 983 результата, 44 622
append-only odds snapshot, 81 event match и 630 сохранённых прогнозов/решений. Все
630 решений — `skip`; реальные Telegram-алерты отключены. Найдено 303 ряда
event/market/selection/line с более чем одним фактическим значением odds, то есть
движение линии действительно накапливается, а не перезаписывается.

Инженерный контур сбора, RAW archive, normalization, matching, leakage-safe features,
baseline/ML evaluation, prediction persistence, settlement, Telegram и Compose готов.
Для включения алертов всё ещё требуются накопленная forward-линия, подтверждённые
результаты соответствующего source и непересекающийся betting backtest.
